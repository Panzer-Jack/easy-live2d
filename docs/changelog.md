# 更新日志

记录 easy-live2d 各版本对使用方有影响的更新，按版本倒序排列。历史内容根据仓库 Git 标签及提交记录整理，日期采用标签所指提交的日期，不代表 npm 发布时间。

## 未发布 — 计划 1.0.0-uat.0

待发布的 Cubism R5 升级与运行修复。本地包版本号仍是 `0.4.4`，本轮尚未执行发布。

### 兼容性变更

- Core、Framework 和调用层配套升级至 Cubism 5 SDK for Web R5。Framework 固定为官方 `5-r.5` 标签（`198a376`）。
- 运行环境要求 WebGL 2，不再回退 WebGL 1。使用方需要同步替换部署的 Core 文件，并更新缓存版本。
- 旧 `.moc3` 模型无需仅为本次 SDK 升级重新导出。迁移步骤见 [Cubism R5 升级](./guide/cubism-r5-migration.md)。

### 新增

- 将 R5 官方着色器内置到库产物，无需额外部署 Shaders 目录。
- 提供 `pnpm setup:cubism`，校验并安装固定版本的 Core 和官方示例模型。
- 新增浏览器回归测试，覆盖旧模型、新版离屏绘制、多模型共存及异常加载。
- 新增中英文更新日志和文档导航入口。

### 修复

- 修复销毁单个模型时释放共享 Framework、影响其他存活模型的问题；支持全部销毁后重新加载。
- 修复加载中销毁、重复销毁和初始化失败时的资源清理，加载中销毁会取消请求。
- 模型或纹理加载失败时拒绝 `ready` Promise，避免一直等待或每帧重复请求；在 ready 事件中销毁不影响已成功的 Promise。
- 修复 Cubism 绘制后 WebGL 状态及 Pixi 缓存不同步导致的叠加渲染问题。

- 同步 ready 回调抛错后保持模型可用；初始化失败后完整移除交互与 resize 监听。
- 补齐 stencil 与纹理上传的状态恢复，上传异常时删除未完成的 GPU 纹理。
- 修复首帧计时，长时间暂停后的单次更新最多推进 100ms。
- 每个精灵独立管理语音，播放与口型共用一次下载、解码；停止/销毁取消待完成操作，播放结束后释放音频实例。
- 重播缓存动作时清空旧回调，动态动作加载失败时释放预约优先级。
- 已声明的模型资源加载失败时报告 URL 与 HTTP 状态。

### 简化

- 直接复用缓存纹理，移除重复加载包装、无用模型字段、重复 JSON 编码和未使用的运行依赖。
- 无实际作用的 `ticker` 字段保留兼容并标记废弃，示例不再传入；Pixi 默认使用 WebGL 2，无需重复填写渲染选项。
- 同步 README、指南、API、迁移说明和示例目录 README。
- 项目自身代码的包元数据及文档许可声明统一以根目录 `LICENSE` 的 MIT 为准，第三方许可保持不变。

### 验证

- 25 项浏览器测试通过，包括 12 项模型回归和 13 项运行边界验证。升级阶段对 Hiyori、Haru 的 5 组固定时间步对比中，参数差为 0、截图一致；该对比不覆盖音频或所有设备。
- Ren 模型的新版离屏绘制通过。具体环境和覆盖限制见 [R5 升级验证记录](./reports/cubism-r5-validation.md)。

## 0.4.4 — 2026-04-15

- 修复动作分组缺失时的处理，并限制空闲动作重复触发，避免每帧产生 Promise rejection。

## 0.4.3 — 2026-04-11

- 新增动作音效自动播放，通过 `Config.MotionSound` 控制。
- `redirectPath` 支持动作音效 URL，并补齐默认重定向结构中的 `MotionSounds` 字段。
- `Live2DSprite` 新增参数值读写方法；修复 `setParameterValueById` / `setParameterValueByIndex` 的设置无法跨帧保持的问题。
- 补充参数控制、动作音效及本地 Core / 子模块配置文档。

## 0.4.2 — 2026-04-09

- 新增基于 Promise 的 `sprite.ready`，可等待模型加载完成。
- 新增获取模型动作和表情的方法。
- 支持通过索引设置表情。

## 0.4.1 — 2026-04-09

- 新增 `Config.crossOrigin`，允许配置 WebGL 纹理加载的跨域方式。
- 修复包版本号格式，补充相关配置文档。

## 0.4.0 — 2026-04-04

- 新增基于 Vue 的 Tauri 示例应用。

## 维护方式

日常变更先加入「未发布」，按需要分为兼容性变更、新增、修复和文档。发布时将条目移到实际版本号下并填写日期，同时更新英文日志。记录用户可感知的变化、升级操作和必要的验证结果，不将未发布内容归入已有版本。
